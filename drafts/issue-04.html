Write your AI agent’s limits before you switch it on

Hi,

Every pitch for an AI agent shows it doing something impressive on its own. In October, American Express and ServiceNow both shipped systems for agents — and both started with what an agent must not do.

Plus, at the bottom: why telling an agent “don’t” isn’t a limit.

The argument

On 13 October, American Express introduced a framework that records what a customer actually asked for — which shop, the maximum budget — before an agent can buy anything. The agent then pays with a token carrying those limits, not the real card number.

Two days later, ServiceNow announced AI Passport: a signed credential saying what an agent is allowed to do, checked while it works. In their demo, an agent allowed refunds under $25 pushed an $18 refund straight through. A $40 one was stopped mid-run, because it was over the limit that needs a person to review it.

You don’t need either product. Copy the order they worked in: limits first, abilities second. Before any agent goes live, write one page — what it can read, what it can change, what it can spend, what it must hand to a person, who gets told, and how you switch it off.

Myth of the issue

“If you tell an AI agent not to do something, it won’t.”

An instruction is something the agent reads. A limit is something the system checks. ServiceNow’s $40 refund wasn’t stopped because the agent remembered a rule — it was stopped because the refund was checked against one at the moment it was attempted.

Instructions get misread, forgotten in a long conversation, or argued around by a determined customer. So when you choose a tool or a builder, ask one question: if the agent tries to break the rule, what stops it? “We told it not to” is not an answer.
